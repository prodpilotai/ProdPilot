## 2. reference/cli.md: four new commands

Add after the `prodpilot serve` section:

````md
## prodpilot audit

```
prodpilot audit [PROJECT] [--ci] [--min-score N] [--fail-on p0|p1|none] [--baseline REF]
```

Audits the project read-only and checks it is ready. `--fail-on` (default `p0`)
fails when a rule at that priority or above fails. `--min-score` fails under a
score. `--baseline` audits the project at another Git ref, in a temporary
worktree that is always removed, and fails when the score dropped or any rule
that passed there now fails. `--ci` prints a JSON summary and never prompts.

Exit codes: 0 passed, 1 the readiness check failed, 2 a tool or usage error. A
shallow clone cannot resolve the baseline; set `fetch-depth: 0` on
`actions/checkout`.

## prodpilot report

```
prodpilot report --format sarif|md|html --out PATH [PROJECT]
```

Writes a SARIF 2.1.0 log for GitHub code scanning, a Markdown report or a
self-contained HTML report. Exits 0 whenever the report was written, whatever
the audit found. No format prints a credential.

## prodpilot fix --dry-run

```
prodpilot fix --dry-run [PROJECT] [--rule RULE_ID]
```

Shows every change the fix loop would make, as unified diffs in loop order, and
writes nothing. Delegated rules show their constraint contract instead of a
diff.

## prodpilot deploy

```
prodpilot deploy [PROJECT] [--branch main] [--no-rollback]
```

Runs the nine deploy stages, as the `prodpilot_deploy` tool does. A project
already deployed by ProdPilot is redeployed to its service, and a deploy that
fails its smoke test is rolled back unless `--no-rollback` is given. Exits 0
when every stage passed and 1 when one stopped the run.
````

## 3. New page: prodpush/rollback.md

```md
---
title: Rollback
description: A redeploy that fails its smoke test is rolled back to the previous version.
---

When ProdPilot deploys a project it already deployed, it deploys to the same
Render service. If that deploy then fails the smoke test, ProdPilot rolls the
service back to the last deploy that was live before it and built a different
commit, waits for the rollback to go live, checks the health path again and
reports both results. CI/CD wiring does not run afterwards.

A service's first deploy has nothing to roll back to, and the report says so. A
rollback that fails or does not go live stops the run with both failures and the
dashboard address; it is never retried. Render keeps builds only for a limited
number of recent deploys, so an old deploy may no longer be available to roll
back to.

Rollback is on by default. `prodpilot deploy --no-rollback`, or `rollback: false`
on the deploy tool, leaves a failed deploy in place as 1.0.0 did.

Observed on the live demo: a broken deploy was rolled back and healthy again in
16.6 seconds, and a rollback to a month-old deploy was refused by Render and
reported as such.
```

Add it to the ProdPush sidebar after "Smoke test".

## 4. New page: getting-started/ci.md, "Use in CI"

```md
---
title: Use in CI
description: Check production readiness on every push and pull request.
---

```yaml
name: Production readiness

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read
  security-events: write

jobs:
  prodpilot:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0
      - uses: prodpilotai/ProdPilot@v1
        with:
          fail-on: p0
          min-score: "70"
```

The action installs ProdPilot pinned exactly, uploads the findings to code
scanning, writes a report to the job summary and fails the job when the project
is not ready. On a pull request it also fails when a rule that passed on the
base branch now fails. It needs no secret. Where code scanning is not available,
the upload is skipped with a notice and the job is still decided by the check.

Inputs: `version`, `path` (default `.`), `min-score`, `fail-on` (default `p0`),
`baseline` (default: the pull request's base commit) and `sarif` (default
`true`).
```

## 1.1.0, 10 October 2026

A hardening release. The ruleset, scoring, model and gate are unchanged from
1.0.0.

### Added

- `prodpilot audit` for CI, with `--ci`, `--min-score`, `--fail-on` and `--baseline`, and exit codes 0, 1 and 2.
- `prodpilot report --format sarif|md|html`, with SARIF for GitHub code scanning.

- An end-of-life notice for the declared Node version.

### Changed

- Rollback is on by default.
- A project already deployed is redeployed to its service instead of getting a second one.
- Generated Dockerfiles and workflows use the declared Node LTS line, Node 24 by default, instead of Node 20.

### Fixed

- A second deploy stopped at the push stage when the only untracked file was `.env.prodpilot`.
- The package reported its version as `1.0.0rc1`.
