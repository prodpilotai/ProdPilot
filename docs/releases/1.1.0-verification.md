# ProdPilot 1.1.0 verification

Live and release checks for 1.1.0, recorded as they were run. Times are UTC.

## Rollback after a failed smoke test (Module 5)

Approved at STOP 5-a. The only service touched was the demo:

| | |
| --- | --- |
| Render service | `srv-dai7ode7bikc73do17u0` (`prodpilot-demo`, free web service) |
| Address | https://prodpilot-demo.onrender.com |
| Repository | `github.com/sudais-khalid/prodpilot-demo`, branch `main` |
| ProdPilot | `main` at `67205bd`, run as `prodpush.run(..., rollback=True)`, the code behind `prodpilot deploy` |

Method. In a clone of the demo repository, the `/api/v1` handler was changed to
throw, so `/api/v1` answers 500 while `/health` still answers 200. The change was
committed and ProdPilot was run on the clone: it passed the gate, the local
Docker build test, pushed the commit and redeployed the existing service. The
service's autodeploy and the repository's deploy workflow were paused for each
run so ProdPilot's deploy was the only one, and both were turned back on at the
end. After each run the broken commit was reverted on `main`.

### Run 1, 2026-10-10: the rollback fails, and is reported once

| Step | Result |
| --- | --- |
| Live before | `dep-dai82amk1f9s73cncsmg`, commit `3057cc4`, built 2026-09-11; `/health` 200, `/api/v1` 200 |
| Broken commit | `7db204a` |
| Redeploy | `dep-db4remd9fdbs73akrb40`, created 03:56:09, live 03:56:45 |
| Smoke test | failed: `/api/v1 returned 500, the service errored` |
| Rollback target | `dep-dai82amk1f9s73cncsmg`, the previous live deploy of a different commit |
| Rollback | `POST /services/srv-dai7ode7bikc73do17u0/rollback` returned **500 internal server error** |
| ProdPilot's report | `Rolling back to deploy dep-dai82amk1f9s73cncsmg failed too: RenderError: ... returned 500: internal server error. Check the service at https://dashboard.render.com/web/srv-dai7ode7bikc73do17u0` |
| Retries | none; the run stopped at the smoke test stage and CI/CD wiring was not reached |
| Whole run | 89.1 s |

Likely cause. Render keeps build artifacts only for a limited number of recent
deploys, depending on the workspace plan, and a deploy can be rolled back to only
while its artifact exists (render.com/docs/rollbacks). The target was a month
old. Render answered with a 500 rather than a 4xx, so the reason was not stated
by Render itself.

Restore. The revert `3b9c606` was pushed while autodeploy was paused, so it was
deployed directly: `dep-db4rf7t9fdbs73akt2cg`, live in 47.7 s, `/health` 200,
`/api/v1` 200. `/api/v1` answered 500 for about 80 seconds in all.

What this run verified: the failure path. A rollback that fails stops the run
with both failures and the dashboard address, and is not retried.
